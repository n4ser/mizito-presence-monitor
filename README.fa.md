# پایش اتصال میزیتو با PHP و هشدار بله — ویژه هاست سی‌پنل

**Mizito Presence Monitor** یک پروژه مستقل برای پایش اتصال Socket.IO میزیتو روی هاست اشتراکی PHP است؛ بدون Node.js، VPS، Composer یا روشن بودن رایانه شخصی. از طریق Cron اجرا می‌شود و هنگام خرابی ارتباط یا بازیابی آن، در پیام‌رسان **بله** اطلاع می‌دهد.

[English README](README.md) · [نمونه تنظیمات](config.example.php) · [لایسنس MIT](LICENSE)

> **مهم:** این پروژه رسمی یا مورد تأیید میزیتو و بله نیست. برقراری WebSocket و ارسال `authenticate` به معنای تأیید ورود یا روشن ماندن علامت سبز آنلاین نیست. حتماً وضعیت را با یک حساب دوم بررسی کنید و شرایط استفاده میزیتو و شرکت هاستینگ را رعایت کنید.

## امکانات

- یک Cron اصلی با اجرای دقیقه‌ای؛ تمام کارهای پایش و هشدار در همان Cron است.
- اتصال امن `wss` و پاسخ Heartbeat (پینگ/پونگ) پروتکل Engine.IO.
- ساعت خاموشی قابل‌تغییر در فایل تنظیمات؛ نیازی به دستکاری فایل `Schedule.php` نیست.
- هشدار خطا پس از ۲ اجرای ناموفق، یادآوری هر ۳۰ دقیقه، و پیام بازیابی در اولین اجرای سالم.
- جلوگیری از اجرای هم‌زمان دو اسکریپت و ذخیره خصوصی لاگ‌ها و وضعیت اعلان‌ها.
- تست اتصال شبکه بدون توکن و تست یک‌باره ارسال پیام در بله.

## نصب سریع روی cPanel

۱. محتویات پروژه را بیرون از `public_html` و **بیرون از ریشه هر دامنه یا ساب‌دامنه** در پوشه‌ای مثل این قرار دهید:

```text
/home/CPANEL_USER/mizito-private/
```

نام کاربری سی‌پنل و مسیر `home` ممکن است روی هاست شما متفاوت باشد (مثلاً `/home3/...`). مسیر واقعی را از File Manager پیدا کنید.

۲. از فایل `config.example.php` کپی بگیرید و نام کپی را `config.php` بگذارید. این فایل خصوصی است و نباید روی GitHub یا داخل پوشه وب قرار گیرد.

۳. مقدارهای زیر را **فقط داخل فایل خصوصی هاست خودتان** تنظیم کنید:

```php
<?php
return [
    'token' => 'YOUR_MIZITO_SESSION_TOKEN',
    'run_seconds' => 52,
    'quiet_hours' => [
        ['00:00', '07:00'],
        ['12:00', '12:30'],
    ],
    'bale_bot_token' => 'YOUR_BALE_BOT_TOKEN',
    'bale_chat_id' => 'YOUR_NUMERIC_CHAT_ID',
    'alert_after_failures' => 2,
    'alert_repeat_minutes' => 30,
];
```

در بله به ربات خود `/start` بفرستید. توکن و Chat ID را در گفتگوها یا Issues گیت‌هاب ارسال نکنید.

۴. در **Cron Jobs** گزینه `Once Per Minute` را بزنید (زمان‌بندی `* * * * *`) و فقط این دستور را در Command وارد کنید؛ `CPANEL_USER` و مسیر هاست را اصلاح کنید:

```bash
/usr/local/bin/php /home/CPANEL_USER/mizito-private/presence.php >> /home/CPANEL_USER/mizito-private/cron-error.log 2>&1
```

۵. پس از چند دقیقه لاگ اصلی را در `runtime/presence.log` بخوانید. اگر خطای PHP رخ دهد، `cron-error.log` را بررسی کنید. فقط همین **یک Cron دائمی** باید وجود داشته باشد.

## تغییر ساعات کار و استراحت

تمام ساعت‌ها به وقت `Asia/Tehran` هستند. بازه‌ها به معنای **خاموش بودن اتصال از سمت هاست** هستند:

| بازه | رفتار |
| --- | --- |
| ۰۰:۰۰ تا ۰۷:۰۰ | توقف تلاش برای اتصال و هشدار معمول |
| ۰۷:۰۰ تا ۱۲:۰۰ | فعال |
| ۱۲:۰۰ تا ۱۲:۳۰ | توقف |
| ۱۲:۳۰ تا ۲۴:۰۰ | فعال |

برای تست موقت شبانه‌روزی، در `config.php` تنظیم کنید:

```php
'quiet_hours' => [],
```

بعد از آزمایش بازه‌های قبلی را برگردانید. برای تغییر برنامه دیگر نیازی به ویرایش فایل‌های داخلی پروژه نیست. اگر از موبایل/مرورگر دیگری نیز متصل باشید، خاموشی این اسکریپت الزاماً شما را آفلاین نمی‌کند.

## تست‌های یک‌باره

اگر Terminal/SSH دارید، این دستورها را روی هاست اجرا کنید. اگر ندارید، برای هرکدام **یک Cron موقت** بسازید و بلافاصله بعد از دریافت نتیجه حذف کنید:

```bash
# فقط اتصال WSS را می‌سنجد؛ بدون توکن
/usr/local/bin/php /home/CPANEL_USER/mizito-private/scripts/probe.php

# ارسال یک پیام تست در بله؛ برای جلوگیری از تکرار، فایل .done ایجاد می‌کند
/usr/local/bin/php /home/CPANEL_USER/mizito-private/scripts/test-bale.php
```

برای تکرار تست بله، فایل `runtime/bale-test.done` را حذف کنید و تست را تنها یک بار اجرا کنید. **کرون تست را دائمی نگذارید.**

## ارسال هشدار چه زمانی است؟

- دو اجرای ناموفق متوالی: هشدار اولیه.
- ادامه همان خطا: یادآوری با فاصله حداقل ۳۰ دقیقه.
- `terminated` یا رد اتصال Socket.IO: هشدار **احتمال** رد شدن نشست؛ نه تشخیص قطعی انقضای توکن.
- اتصال دوباره پایدار شود: پیام بازیابی، بدون تأخیر اضافه سه‌دقیقه‌ای.
- ساعت خاموشی: نه تلاش برای اتصال و نه هشدارهای معمول.
- خاموشی کامل هاست یا توقف خود Cron: **از همان هاست هشداری ارسال نمی‌شود**؛ برای چنین رخدادی مانیتور بیرونی لازم است.

## درباره توکن میزیتو

توکن موجود را در `config.php` نگه دارید. تا وقتی معتبر باشد، دریافت دوباره لازم نیست. در این پروژه **تمدید خودکار توکن پیاده‌سازی نشده** چون روش رسمی و امن آن تأیید نشده است. خالی کردن توکن برای آزمایش، فقط خطای تنظیمات را تست می‌کند؛ تغییر چند حرف توکن لزوماً هشدار انقضا تولید نمی‌کند.

## ارتقا از نسخه قبلی V3

قبل از جابه‌جایی، از `config.php` نسخه پشتیبان بگیرید. ساختار جدید فایل‌های کلاس را به `src/` و فایل‌های تست را به `scripts/` منتقل می‌کند. Cron همچنان `presence.php` را اجرا می‌کند. فایل تنظیمات قبلی بدون حذف شدن قابل استفاده است؛ اگر `quiet_hours` در آن تعریف نشده باشد، بازه پیش‌فرض اعمال می‌شود. وضعیت و لاگ جدید در پوشه `runtime/` نوشته می‌شود و فایل قدیمی `alert-state.json` عمداً وارد نمی‌شود؛ ممکن است برای خطای موجود یک هشدار تازه بیاید.

## امنیت و محدودیت‌ها

**امنیت:** همه فایل‌ها را خارج از ریشه وب نگه دارید؛ بهتر است مجوز `config.php` برابر `600` باشد (اگر هاست پشتیبانی می‌کند). `.gitignore` توکن‌ها، لاگ‌ها و وضعیت اعلان‌ها را از Git حذف می‌کند. بااین‌حال قبل از Push فایل‌ها را بررسی کنید. افشای توکن میزیتو یا بله نیازمند تعویض فوری آن است.

**محدودیت فنی:** اتصال WebSocket و ارسال پیام احراز هویت، دلیل قطعی پذیرفته‌شدن توکن یا آنلاین دیده‌شدن شما توسط اعضای تیم نیست. اجرای ۵۲ ثانیه‌ای Cron دقیقه‌ای چند ثانیه فاصله بدون اتصال ایجاد می‌کند. هاست اشتراکی ممکن است اجرای PHP طولانی را متوقف کند یا استفاده از این الگو را محدود بداند. با پشتیبانی هاست خود هماهنگ کنید. این پروژه هیچ تضمینی برای «همیشه سبز ماندن» ندارد.

## اجرای تست توسعه‌دهنده

```bash
php tests/run.php
find . -name '*.php' -print0 | xargs -0 -n1 php -l
```

پروژه با PHP 8.1 یا بالاتر اجرا می‌شود و به بسته Composer نیاز ندارد. مشارکت و Pull Request خوش‌آمد است؛ لطفاً توکن، آدرس‌های امضاشده و لاگ‌های خصوصی را منتشر نکنید.

**برچسب‌های مناسب گیت‌هاب:** `php`, `mizito`, `socketio`, `websocket`, `cron`, `cpanel`, `bale-messenger`, `monitoring`, `persian`, `shared-hosting`.
